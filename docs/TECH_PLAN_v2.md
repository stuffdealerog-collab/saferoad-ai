## 2. Обновлённый конвейер

```text
Загруженный MP4 / поток CCTV
        ↓
[0] Инжест и нормализация
    (реальные PTS, детекция VFR/потерянных кадров, отклонение непригодного видео)
        ↓
[1] Детекция объектов (YOLO)
        ↓
[2] Многообъектный трекинг (ByteTrack / BoT-SORT)
        ↓
[3] Гейт качества треков
    (мин. длина, confidence, непрерывность; мусор — в карантин, не в анализ)
        ↓
[4] Калибровка / гомография + маска валидности
    (проекция bottom-center → плоскость дороги; треки вне маски помечаются)
        ↓
[5] Оценка состояния (motion)
    (фильтр Калмана / RTS-сглаживание на плоскости дороги →
     позиция, скорость, ускорение, heading С ОЦЕНКОЙ НЕОПРЕДЕЛЁННОСТИ)
        ↓
[6] Геометрия сцены
    (конфликтные зоны, манёвры, переходы — из конфигурации камеры)
        ↓
[7] Движок конфликтов
    (TTC — только при валидных допущениях; PET — только относительно зон;
     мин. дистанция, относительная скорость, замедление, угол конфликта)
        ↓
[8] Классификация near-miss
    (правила с гистерезисом и мин. длительностью; reason codes)
        ↓
[9] Risk score (конфигурируемые веса, помечен «экспериментальный»)
        ↓
[10] Доказательства: аннотированные клипы + структурированные события (JSON)
        ↓
[11] Дашборд
```

Каждая стадия сериализует свой выход на диск (см. §10). Любую стадию можно перезапустить отдельно.

## 3. Инжест и нормализация (новый модуль)

Реальное CCTV теряет кадры, использует переменную частоту кадров и врёт в метаданных. Все временные метрики (TTC, PET, скорость) зависят от корректного времени, поэтому:

- извлечение **presentation timestamps (PTS)** каждого кадра через PyAV/ffprobe; никогда не считать `t = frame_idx / fps_nominal`;
- детекция VFR: если std интервалов между кадрами превышает порог — видео помечается, интервалы используются фактические;
- детекция потерянных кадров (разрывы PTS) — фиксируются в отчёте инжеста; треки через разрыв не интерполируются молча;
- **критерии отклонения** (видео не принимается в анализ, причина — явная): фактический FPS < 10; разрешение < 720p в зоне анализа; PTS невосстановимы; доля потерянных кадров > 5%;
- транскодирование в нормализованный промежуточный формат с картой «кадр → PTS».

Выход: `ingest_report.json` (фактический FPS, VFR-статус, разрывы, вердикт пригодности) + нормализованное видео.

## 4. Конфигурация камеры

Один YAML на камеру. Всё, что зависит от геометрии сцены, живёт здесь — не в коде.

```yaml
camera_id: tashkent_xx_001
video:
  expected_resolution: [1920, 1080]
calibration:
  method: manual_homography
  image_points: [[x1,y1], [x2,y2], [x3,y3], [x4,y4], ...]   # >= 4, лучше 6–8
  ground_points_m: [[X1,Y1], ...]                            # метры, локальная СК
  homography: [[...], [...], [...]]                          # вычисляется, кэшируется
  reprojection_error_m: {mean: ..., max: ...}                # обязательное поле
  validity_mask: polygon_image_coords                        # зона, где ошибка ограничена
  ground_plane_assumption: flat                              # явное допущение
geometry:
  conflict_zones:                                            # без них PET не вычисляется
    - id: crosswalk_north
      type: pedestrian_crossing
      polygon_ground_m: [...]
    - id: intersection_core
      type: junction
      polygon_ground_m: [...]
  movements:                                                 # опорные траектории манёвров
    - id: right_turn_east_to_south
      path_ground_m: [...]
thresholds_profile: experimental_v1                          # ссылка на профиль порогов
```

Правила:

- гомография пересчитывается из точек при изменении конфига; ошибка репроекции публикуется в каждом отчёте анализа;
- **маска валидности** обязательна: позиции вне маски не участвуют в вычислении скоростей и конфликтов (трек продолжает существовать, но помечен `outside_calibrated_area`);
- допущение плоской земли — явное поле; уклон/съезд = отдельный метод калибровки в будущем, не молчаливая ошибка;
- точка контакта с землёй — bottom-center бокса, с флагом деградации при частичной окклюзии (видимый низ ≠ колёса).

## 5. Трекинг и гейт качества треков

Качество трекинга важнее точности детекции. Метрики здоровья считаются на каждом прогоне:

- частота ID-switch (на минуту и на пересечение зоны);
- частота фрагментации (треки короче N секунд / общее число);
- доля кадров с окклюзией по классам.

**Гейт качества** (стадия [3]) — трек попадает в анализ безопасности, только если:

- длина ≥ `min_track_duration_s` (по умолчанию 1.0 с) и ≥ `min_track_points` (по умолчанию 8);
- средний confidence детекций ≥ порога класса;
- нет физически невозможных скачков (порог по классу: пешеход ≤ 4 м/с, авто ≤ 40 м/с между кадрами) — скачок = кандидат на склейку двух объектов, трек уходит в карантин `quarantine/`, а не в конфликты;
- разрыв длиннее `max_gap_s` (по умолчанию 0.5 с) разрезает трек на два — молчаливой интерполяции через окклюзию нет.

Карантин сериализуется и просматривается в инструменте ревью: это источник данных о сбоях трекинга для золотого набора.

## 6. Модуль motion: оценка состояния вместо дифференцирования

Прямое дифференцирование позиций умножает шум: дрожание бокса в 2–5 px после гомографии на дальнем крае сцены — это метры, а после двух производных — фиктивные «резкие торможения». Поэтому:

- **фильтр Калмана на плоскости дороги** (модель постоянного ускорения или CTRV) на каждый трек; для офлайн-анализа — **RTS-сглаживание** (вперёд-назад), дающее несмещённые оценки без лага;
- скорость, ускорение, heading берутся **только** из оценённого состояния, никогда из сырых разностей;
- ковариация состояния распространяется в метрики: у каждой скорости есть σ; «37 км/ч ± 4»;
- heading не определён при скорости ниже `min_speed_for_heading` (0.5 м/с) — у стоящего пешехода нет направления;
- шум измерений масштабируется по позиции в кадре: дальше от камеры → больше неопределённость (из якобиана гомографии);
- «резкое торможение» = замедление ниже порога, устойчивое ≥ `min_braking_duration_s` (0.4 с) с учётом σ — одиночный выброс не событие.

Юнит-тесты: синтетические траектории с известной аналитической скоростью/ускорением + инжектированный шум; фильтр обязан восстановить истину в заданном допуске.

## 7. Движок конфликтов: границы применимости метрик

**TTC** вычисляется только когда её допущения валидны: сближение по прогнозируемым траекториям, относительная скорость выше порога, оба трека внутри маски валидности, σ скоростей ниже порога. Для всех прочих пар TTC = `not_applicable` с причиной, не «большое число».

**PET** вычисляется только относительно зон из `geometry.conflict_zones`. Разрешение PET ограничено фактическим FPS: при 12.5 fps шаг 80 мс — PET публикуется с этой дискретностью, различия внутри шага не интерпретируются.

**Минимальная прогнозируемая дистанция** — по прогнозу состояния на горизонте ≤ 2 с; горизонт и модель прогноза — часть конфигурации, экстраполяция дальше 2 с запрещена.

**Угол конфликта** — классификация (пересечение / слияние / попутный / поворот / пешеходный) по манёврам из `geometry.movements`, а не по мгновенному углу векторов скорости.

Каждая метрика в событии несёт: значение, единицы, σ или флаг качества, и причину невычислимости, если не вычислена. Аналитические сбои не глотаются (принцип №10 v1 — сохранён).

## 8. Классификация near-miss

Без изменений по сути (правила, прозрачные пороги, reason codes), с тремя ужесточениями:

1. **Гистерезис и минимальная длительность**: событие открывается при пересечении порога входа, закрывается по порогу выхода; события короче `min_event_duration_s` (0.3 с) отбрасываются — мигание TTC на границе порога не порождает поток событий;
2. **События из треков карантина невозможны** — фантомные конфликты от склеенных/разорванных треков отсекаются до классификации;
3. Все пороги живут в версионируемом профиле `thresholds_profile` (`experimental_v1`, …) — в каждом событии записан ID профиля, которым оно порождено. Пороги помечены экспериментальными до валидации на золотом наборе. Risk score — индекс приоритизации, **никогда** не вероятность аварии.

Схема `ConflictEvent` из v1 сохраняется и расширяется полями: `uncertainty`, `thresholds_profile_id`, `calibration_error_m`, `track_quality_a/b`, `not_applicable_reasons`.

## 11. Валидация — теперь предусловие, а не финал

**Золотой набор** (создаётся на вехе 3, до движка конфликтов): 30–50 клипов по категориям — норма, близкие взаимодействия, настоящие near-miss, спорные случаи, сбои трекинга. Разметка: `NearMiss: yes/no/uncertain`, severity, тип конфликта, участники.

**Инструмент разметки** — минимальный веб-интерфейс: клип + покадровый скраб + форма разметки; он же используется для ревью событий системы (подтвердить/отклонить) — каждое ревью пополняет обучающие данные.

**Обязательные проверки до любого правительственного демо:**

1. каждое показываемое событие проверено человеком;
2. ошибка оценки скорости измерена по эталону (проезд GPS-логгера через откалиброванную сцену или промеренная разметка) и опубликована;
3. ошибка репроекции калибровки — в отчёте по каждой камере;
4. ложные срабатывания в час записи + event-level precision/recall на золотом наборе;
5. частота ID-switch и фрагментации на репрезентативных записях.

Различие сохраняется явно: *техническая точность детекции* ≠ *предсказательная связь с будущими ДТП*. Второе — установлено в литературе по суррогатным мерам (Traffic Conflict Technique, SSAM, EVT-модели), но не валидировано на нашем развёртывании, и так и формулируется.

## 12. Пересмотренные вехи

| Веха | Содержание | Критерий выхода |
|---|---|---|
| **0. Данные и инжест** | Получить реальные записи узбекских перекрёстков; модуль инжеста | ≥ 5 часов пригодного видео с ≥ 2 ракурсов; ingest_report работает |
| **1. Детекция + трекинг** | YOLO + ByteTrack/BoT-SORT, гейт качества, метрики здоровья | ID-switch и фрагментация измерены; карантин работает |
| **2. Калибровка** | Гомография, маска валидности, ошибка репроекции | Ошибка скорости по GPS-эталону ≤ 15% в маске валидности |
| **2.5. Motion** | Калман/RTS на плоскости дороги, неопределённости | Синтетические тесты проходят; нет ложных «торможений» на постоянной скорости |
| **3. Инструмент разметки + золотой набор** | Веб-разметчик; 30–50 размеченных клипов | Набор покрывает все 5 категорий |
| **4. Геометрия + движок конфликтов** | Зоны, манёвры, TTC/PET/дистанция/угол — на золотом наборе | Метрики совпадают с ручным расчётом на синтетике; PET вычисляется только в зонах |
| **5. Near-miss** | Правила, гистерезис, reason codes, профили порогов | Precision ≥ 70% на золотом наборе (цель первой итерации) |
| **6. Доказательства** | Клипы, аннотированное видео, оверлеи | Ревьюер восстанавливает причину события из клипа без кода |
| **7. Дашборд** | Загрузка, анализ, лента событий, аналитика | Полный цикл: MP4 → события → ревью в браузере |
| **8. Расширенная валидация** | Больше данных, межразметчицкое согласие, калибровка порогов | Опубликованный отчёт точности |
| **9. Мультикамерность / город** | Только после доверия к одной камере | — |

Вехи 0–2.5 — фундамент точности; вехи 3–5 намеренно идут через разметку. Веха 9 не начинается, пока precision на одной камере не подтверждён.

## 13. Явные допущения (реестр)

Все допущения системы собраны в одном месте и наследуются документацией:

1. Земля в зоне анализа плоская (поле в конфиге камеры).
2. Bottom-center бокса ≈ точка контакта с землёй; деградирует при окклюзии и наклоне двухколёсных.
3. Прогноз траекторий валиден ≤ 2 с.
